# ComfyUI Workflow Architecture & Automation

> **Domain-specific Skill.** ComfyUI represents generative diffusion pipelines as directed acyclic graphs (DAGs) of computational nodes. Use this skill when designing, inspecting, converting, or automating ComfyUI workflows for text-to-image, image-to-image, inpainting, ControlNet conditioning, and video synthesis.

---

## When to Activate

- Designing or refactoring ComfyUI node graphs (SD 1.5, SDXL, SD 3.5, Flux, AnimateDiff).
- Converting standard GUI workflow JSON (`workflow.json`) to ComfyUI execution API format (`prompt.json`).
- Building backend or CLI automation to queue and monitor generations via ComfyUI REST API & WebSocket.
- Integrating LoRA weights, ControlNet guidance, IP-Adapter embeddings, or latent upscalers.
- Diagnosing execution errors: missing custom nodes, tensor dimension mismatches, CUDA VRAM exhaustion.

---

## Architecture: GUI Graph vs API Prompt Format

ComfyUI has **two distinct JSON representations**:

1. **GUI Workflow Format (`workflow.json`)**:
   - Contains canvas coordinates, node titles, colors, visually linked pins (`links` array).
   - Saved by ComfyUI UI via "Save". **Cannot be sent directly to the `/prompt` API**.

2. **API Prompt Format (`prompt.json`)**:
   - Generated by enabling "Enable Dev mode Options" in ComfyUI Settings -> "Save (API Format)".
   - A flat dictionary where keys are node IDs (`"3"`, `"4"`), each containing:
     - `class_type`: Name of the Python node class (e.g. `KSampler`, `CheckpointLoaderSimple`).
     - `inputs`: Dictionary of parameters (strings, floats, ints) and node links as tuples `[node_id_string, output_slot_index]`.

> **Key Rule**: When programmatically triggering ComfyUI via HTTP POST `/prompt`, **always** supply the API Prompt Format, not the GUI canvas format.

## Core Node Archetype Pipeline

A canonical ComfyUI pipeline flows through 5 interconnected stages:

```
[CheckpointLoaderSimple] ──── MODEL ───────────────┐
      │          │                                 │
     CLIP       VAE                                │
      │          │                                 │
      ▼          │                                 │
[CLIPTextEncode] ┼── CONDITIONING (positive) ──────┼──► [KSampler] ── LATENT ──► [VAEDecode] ──► [SaveImage]
[CLIPTextEncode] ┼── CONDITIONING (negative) ──────┤         ▲                          ▲
                 │                                 │         │                          │
                 │     [EmptyLatentImage] ─────────┴─────────┘                          │
                 └──────────────────────────────────────────────────────────────────────┘
```

### Essential Core Nodes

| Node Class | Primary Inputs | Outputs | Purpose |
|------------|----------------|---------|---------|
| `CheckpointLoaderSimple` | `ckpt_name` | `MODEL`, `CLIP`, `VAE` | Loads base weights & text encoder |
| `CLIPTextEncode` | `text`, `clip` | `CONDITIONING` | Converts prompt text into embedding tensor |
| `EmptyLatentImage` | `width`, `height`, `batch_size` | `LATENT` | Initializes latent noise tensor |
| `KSampler` / `KSamplerAdvanced` | `model`, `positive`, `negative`, `latent_image`, `seed`, `steps`, `cfg`, `sampler_name`, `scheduler`, `denoise` | `LATENT` | Executes iterative denoising loops |
| `VAEDecode` | `samples`, `vae` | `IMAGE` | Decodes denoised latents into RGB pixel space |
| `SaveImage` | `images`, `filename_prefix` | None (Saves to disk) | Writes output images to `./output/` directory |
| `LoraLoader` | `model`, `clip`, `lora_name`, `strength_model`, `strength_clip` | `MODEL`, `CLIP` | Applies dynamic LoRA adaptations |

## Automation via ComfyUI REST & WebSocket API

The local ComfyUI server runs on `http://127.0.0.1:8188` by default.

### Key API Endpoints

- **`GET /system_stats`**: Check VRAM usage, device status, and Python environment.
- **`POST /prompt`**: Queue a workflow for execution. Accepts `{"client_id": "...", "prompt": { <api_prompt_json> }}`.
- **`GET /history/{prompt_id}`**: Retrieve execution output details, filenames, and node statuses.
- **`GET /view?filename={filename}&subfolder={subfolder}&type={type}`**: Download generated image binaries.
- **`GET /queue`**: Inspect pending and currently running jobs.
- **`POST /interrupt`**: Immediately halt execution of the running job.

### WebSocket Monitoring (`ws://127.0.0.1:8188/ws?clientId={client_id}`)

To receive real-time execution events, open a WebSocket connection with your unique `client_id` before calling `POST /prompt`:
- `status`: Queue depth and memory status.
- `execution_start`: Triggered when worker begins processing prompt ID.
- `executing`: Emitted with current `node` ID as it begins running.
- `progress`: Current sampling step and maximum steps during `KSampler` execution.
- `executed`: Emitted when a node completes, containing output files and preview thumbnails.

## Best Practices & Gotchas

1. **Latent Sizing Alignment**:
   - Always ensure latent dimensions (`width` and `height`) are multiples of 8 (or 64 for Flux / SDXL) to avoid convolution dimension errors in VAE decoding.
2. **LoRA Stacking Order**:
   - Chain LoRAs sequentially (`LoraLoader` -> `LoraLoader` -> `KSampler`). Keep `strength_clip` between 0.6–0.9 if styling bleeding occurs.
3. **Flux Specifics**:
   - Flux pipelines require `DualCLIPLoader` (t5xxl + clip_l) and specialized guidance (`FluxGuidance` node). Sampler steps can typically be lower (20–25 steps with Euler/Simple).
4. **VRAM Optimization**:
   - Use `--lowvram` or `--medvram` flags when launching ComfyUI on GPUs with ≤ 8 GB VRAM.
   - For batch upscaling, prefer tiled VAE decoding (`VAEDecodeTiled`) to prevent Out-Of-Memory spikes.
